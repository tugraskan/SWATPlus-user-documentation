# Watershed Configuration

SWAT+ represents a watershed as a modular network of **spatial objects** whose counts are declared in [`object.cnt`](../../introduction-1/simulation-settings/object.cnt/README.md) ([`basin_read_objs.f90`](https://github.com/swat-model/swatplus/blob/aa4179fea9c9fbb9b00efc38e3d4def3b6a3f715/src/basin_read_objs.f90#L38)) and whose properties are stored in relational input tables. This object-based structure separates each physical element from its network connections, allowing flexible subbasin, hillslope, floodplain, and stream-network configurations.

The active spatial objects and grouping units fall into the following categories (see [Spatial Objects](spatial-objects.md) for object codes and details):

* **Landscape units and process objects:** Hydrologic Response Units (`hru`), simplified HRU-LTEs (`hru_lte`), Routing Units (`ru`), and Landscape Units (grouping units used for aggregation and output rather than routed `object.cnt` objects).
* **Groundwater objects:** Lumped 1-D Aquifers (`aqu`), or gridded 2-D GWFlow river cells (`gwflow`), which replace aquifers when GWFlow is active with `chancell.gw` ([`basin_read_objs.f90`](https://github.com/swat-model/swatplus/blob/aa4179fea9c9fbb9b00efc38e3d4def3b6a3f715/src/basin_read_objs.f90#L46-L75)).
* **Channels and impoundments:** SWAT-DEG channels (`chandeg`, the active channel object in SWAT+ main `6f515368`) and Reservoirs/Ponds (`res`). Wetlands are simulated on ponded HRUs via [`wetland.wet`](../../introduction-1/wetlands/README.md) rather than as separate `object.cnt` objects.
* **Boundary, scaling, and outlet objects:** Recall point sources/inlets (`recall`), Export Coefficients (`exco`), Delivery Ratios (`dr`), and Outlets (`outlet`).
* **Legacy and unused `object.cnt` slots:** [`object.cnt`](../../introduction-1/simulation-settings/object.cnt/README.md) also parses counts for legacy SWAT channels (`chan`, which read `channel.con` and overbank links in [`hyd_connect.f90`](https://github.com/swat-model/swatplus/blob/aa4179fea9c9fbb9b00efc38e3d4def3b6a3f715/src/hyd_connect.f90#L150-L153) but have no dispatch branch in [`command.f90`](https://github.com/swat-model/swatplus/blob/aa4179fea9c9fbb9b00efc38e3d4def3b6a3f715/src/command.f90#L276)), `canal` and `pump` (which only reserve object-index offsets in [`hyd_connect.f90`](https://github.com/swat-model/swatplus/blob/aa4179fea9c9fbb9b00efc38e3d4def3b6a3f715/src/hyd_connect.f90#L105-L112) without connection files), and unused `aqu2d`, `hrd`, and `wro` counts.

## Connectivity and Water Exchange

* **Gravity-driven routing (`*.con`):** Downslope and downstream routing between spatial objects is configured in [Connectivity](../../introduction-1/connectivity/README.md) files that share the [`'object'.con`](../../introduction-1/connectivity/hru.con/README.md) structure read by [`hyd_read_connect.f90`](https://github.com/swat-model/swatplus/blob/aa4179fea9c9fbb9b00efc38e3d4def3b6a3f715/src/hyd_read_connect.f90#L220-L298). Each outgoing connection specifies a receiving object type (`obj_typ`), receiving object ID (`obj_id`), hydrograph component (`hyd_typ`: `tot`, `sur`, `lat`, `til`, or `rhg`), and routing fraction (`frac`). Network topology and execution order are fixed at startup in [`hyd_connect.f90`](https://github.com/swat-model/swatplus/blob/aa4179fea9c9fbb9b00efc38e3d4def3b6a3f715/src/hyd_connect.f90#L215-L458) and executed each day in [`command.f90`](https://github.com/swat-model/swatplus/blob/aa4179fea9c9fbb9b00efc38e3d4def3b6a3f715/src/command.f90#L276).
* **Auxiliary spatial link files:** [`aqu_cha.lin`](../../introduction-1/connectivity/aqu_cha.lin.md) ([`aqu2d_read.f90`](https://github.com/swat-model/swatplus/blob/aa4179fea9c9fbb9b00efc38e3d4def3b6a3f715/src/aqu2d_read.f90#L35-L76)) distributes an aquifer's return flow across multiple channels in addition to `aquifer.con`, and [`chan-surf.lin`](../../introduction-1/connectivity/chan_surf.lin.md) ([`overbank_read.f90`](https://github.com/swat-model/swatplus/blob/aa4179fea9c9fbb9b00efc38e3d4def3b6a3f715/src/overbank_read.f90#L31-L73)) links channels to floodplain HRUs or objects.
* **Managed (non-gravity) transfers:** Diversions, pumping, treatment plants, municipal/industrial water uses, and inter-basin transfers are configured through [Water Allocation](../../introduction-1/water-allocation/README.md) inputs.
