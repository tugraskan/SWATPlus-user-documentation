# Debugging Outputs

These files record run progress, setup diagnostics, and specialized model quantities. The behavior below follows SWAT+ dev revision `aa4179fe`.

| File | When it is written and what it contains |
| --- | --- |
| `simulation.out` | The main program opens it at startup and writes the version banner. It receives timing and progress messages, including progress from the time controller and the completion message from the main program. [Startup log](https://github.com/swat-model/swatplus/blob/aa4179fea9c9fbb9b00efc38e3d4def3b6a3f715/src/main.f90.in#L27) · [Progress write](https://github.com/swat-model/swatplus/blob/aa4179fea9c9fbb9b00efc38e3d4def3b6a3f715/src/time_control.f90#L167) · [Completion log](https://github.com/swat-model/swatplus/blob/aa4179fea9c9fbb9b00efc38e3d4def3b6a3f715/src/main.f90.in#L166) |
| `success.fin` | The main program opens this file and writes the success message after simulation, enabled calibration, and any SWIFT output. Check the marker for the current run together with the exit status and expected result files. [Simulation and completion](https://github.com/swat-model/swatplus/blob/aa4179fea9c9fbb9b00efc38e3d4def3b6a3f715/src/main.f90.in#L146) |
| `files_out.out` | Basin setup opens the registry. Individual routines add entries for selected filenames by writing to unit 9000. User-named object outputs bypass registration and open on their assigned units. An entry establishes registration. Data rows depend on the corresponding writer. [Registry opener](https://github.com/swat-model/swatplus/blob/aa4179fea9c9fbb9b00efc38e3d4def3b6a3f715/src/proc_bsn.f90#L14) · [Object output opener](https://github.com/swat-model/swatplus/blob/aa4179fea9c9fbb9b00efc38e3d4def3b6a3f715/src/object_read_output.f90#L102) |
| `diagnostics.out` | Basin setup opens the file for messages explicitly written to unit 9001. Entries can report input and configuration problems. On dev these include warnings and errors from the plant database reader (older 54-column `plants.plt`, missing or misplaced lignin columns), the soil test reader (`soil_test.sol` rows naming unknown soils, or files with no rows) and the land-use decision-table reader ([`plant_parm_read.f90`](https://github.com/swat-model/swatplus/blob/aa4179fea9c9fbb9b00efc38e3d4def3b6a3f715/src/plant_parm_read.f90#L244-L330), [`soil_test_read.f90`](https://github.com/swat-model/swatplus/blob/aa4179fea9c9fbb9b00efc38e3d4def3b6a3f715/src/soil_test_read.f90#L95-L202)). The run log and process status provide separate evidence. [Diagnostics opener](https://github.com/swat-model/swatplus/blob/aa4179fea9c9fbb9b00efc38e3d4def3b6a3f715/src/proc_bsn.f90#L17) · [Print-control reader](https://github.com/swat-model/swatplus/blob/aa4179fea9c9fbb9b00efc38e3d4def3b6a3f715/src/basin_print_codes_read.f90#L20) |
| `checker.out` | HRU setup writes a title, headings, units, and one 14-value record per full HRU. These records list soil and hydrology properties. Soil name and hydrologic group occupy the first two positions, whose printed headings are blank. [HRU setup gate](https://github.com/swat-model/swatplus/blob/aa4179fea9c9fbb9b00efc38e3d4def3b6a3f715/src/proc_hru.f90#L23) · [Checker records](https://github.com/swat-model/swatplus/blob/aa4179fea9c9fbb9b00efc38e3d4def3b6a3f715/src/proc_hru.f90#L56) · [Checker headings](https://github.com/swat-model/swatplus/blob/aa4179fea9c9fbb9b00efc38e3d4def3b6a3f715/src/hydrograph_module.f90#L1120) |
| `area_calc.out` | Basin setup opens it, and the connection routine writes area diagnostics for objects other than HRUs and routing units. Each row contains object index, type, number, input area, calculated area, and incoming connection count, followed by six values per incoming connection. [Area opener](https://github.com/swat-model/swatplus/blob/aa4179fea9c9fbb9b00efc38e3d4def3b6a3f715/src/proc_bsn.f90#L20) · [Area records](https://github.com/swat-model/swatplus/blob/aa4179fea9c9fbb9b00efc38e3d4def3b6a3f715/src/hyd_connect.f90#L534) |
| `hydcon.out`, `hydcon.csv` | The `hydcon` print flag enables the connectivity listing. The CSV flag adds the CSV variant. The writer emits headerless rows in command order. It repeats the whole outgoing `obj_out` array inside each outgoing connection group, alongside the type, object number, and hydrograph type for that connection. Row width therefore depends on the outgoing connections and array length. [Connectivity openers](https://github.com/swat-model/swatplus/blob/aa4179fea9c9fbb9b00efc38e3d4def3b6a3f715/src/header_hyd.f90#L8) · [Connectivity records](https://github.com/swat-model/swatplus/blob/aa4179fea9c9fbb9b00efc38e3d4def3b6a3f715/src/hyd_connect_out.f90#L16) |
| `erosion.out` | HRU setup writes the title, erosion headings, and units. The source trace for unit 4001 found only those opening writes. [Erosion opener](https://github.com/swat-model/swatplus/blob/aa4179fea9c9fbb9b00efc38e3d4def3b6a3f715/src/proc_hru.f90#L49) |
| `co2.out` | Basin setup writes year and CO₂ concentration in ppm from the annual series selected by the CO₂ reader. The basin CO₂ value supplies the series when the reader has zero annual input records. [CO₂ opener](https://github.com/swat-model/swatplus/blob/aa4179fea9c9fbb9b00efc38e3d4def3b6a3f715/src/co2_read.f90#L34) · [Fallback and annual series](https://github.com/swat-model/swatplus/blob/aa4179fea9c9fbb9b00efc38e3d4def3b6a3f715/src/co2_read.f90#L66) |
| `paddy_test.csv` | The main program opens the test file and writes 21 headings before simulation. The HRU writer adds 21 values when a wetland configuration is present, the wetland hydrology code is `paddy`, and the depth check `wet_ob(j)%depth > -0.1` passes. Each written value has a following comma, including the final value. [Paddy test opener](https://github.com/swat-model/swatplus/blob/aa4179fea9c9fbb9b00efc38e3d4def3b6a3f715/src/main.f90.in#L143) · [Paddy test rows](https://github.com/swat-model/swatplus/blob/aa4179fea9c9fbb9b00efc38e3d4def3b6a3f715/src/hru_control.f90#L547) |
| `yield.out`, `yield.csv` | The management output flag opens the LTE yield reports. The CSV flag adds `yield.csv`. The LTE writer uses list-directed output for both names and writes seven values. In order, they are LTE HRU number, day of year, year, plant name, leaf area index, dry matter, and yield. [Yield openers](https://github.com/swat-model/swatplus/blob/aa4179fea9c9fbb9b00efc38e3d4def3b6a3f715/src/header_yield.f90#L9) · [LTE yield records](https://github.com/swat-model/swatplus/blob/aa4179fea9c9fbb9b00efc38e3d4def3b6a3f715/src/hru_lte_control.f90#L206) |
