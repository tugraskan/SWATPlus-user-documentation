# Object Outputs

Object print settings request daily hydrograph, soil, plant, or channel floodplain records for selected objects. The input reference in `file.cio` selects the configuration file. A missing file or the literal reference `null` leaves the request count at zero. The writer runs before the standard `print.prt` skipped-year gate. [Missing-file handling](https://github.com/swat-model/swatplus/blob/aa4179fea9c9fbb9b00efc38e3d4def3b6a3f715/src/object_read_output.f90#L19) · [Reader call](https://github.com/swat-model/swatplus/blob/aa4179fea9c9fbb9b00efc38e3d4def3b6a3f715/src/main.f90.in#L61) · [Writer call](https://github.com/swat-model/swatplus/blob/aa4179fea9c9fbb9b00efc38e3d4def3b6a3f715/src/command.f90#L437) · [object.prt settings](../introduction-1/simulation-settings/object.prt/README.md) · [file.cio reader](https://github.com/swat-model/swatplus/blob/aa4179fea9c9fbb9b00efc38e3d4def3b6a3f715/src/readcio_read.f90#L20)

## Request rows

Each row gives the record ID, object type, object number within that type, output code, and filename. **Use consecutive IDs starting at 1, in file order.** The reader stores the fields at the input ID, then resolves the object and opens its file by row position. The filename is stored in 26 characters and passed directly to `OPEN`. The writer uses the selected code's text layout for filenames ending in `.csv` as well. [Row indexing and opening](https://github.com/swat-model/swatplus/blob/aa4179fea9c9fbb9b00efc38e3d4def3b6a3f715/src/object_read_output.f90#L48) · [Request fields](https://github.com/swat-model/swatplus/blob/aa4179fea9c9fbb9b00efc38e3d4def3b6a3f715/src/hydrograph_module.f90#L259)

The reader recognizes `hru`, `hlt`, `ru`, `res`, `cha`, `exc`, `dr`, `out`, and `sdc`. The soil and plant cases use HRU arrays. `cha_fp` uses the simplified channel floodplain record. The reader explicitly maps object number zero to the all-HRU sentinel for type `hru`. Each writer branch handles that value separately. [Object type mapping](https://github.com/swat-model/swatplus/blob/aa4179fea9c9fbb9b00efc38e3d4def3b6a3f715/src/object_read_output.f90#L56) · [Zero object handling](https://github.com/swat-model/swatplus/blob/aa4179fea9c9fbb9b00efc38e3d4def3b6a3f715/src/obj_output.f90#L47)

## Output codes and layouts

The normal prefix has four date values, `jday`, `mon`, `day`, and `yr`, followed by two object fields. The counts below describe the scalar values supplied by the source write lists. They include the date and object fields. [Date and object headings](https://github.com/swat-model/swatplus/blob/aa4179fea9c9fbb9b00efc38e3d4def3b6a3f715/src/hydrograph_module.f90#L963) · [Header selection](https://github.com/swat-model/swatplus/blob/aa4179fea9c9fbb9b00efc38e3d4def3b6a3f715/src/object_read_output.f90#L105)

| Output code | Header and row layout |
| --- | --- |
| `tot`, `rhg`, `sur`, `lat`, `til` | Total, recharge, surface, lateral, and tile hydrographs select slots 1–5 of the object hydrograph. The 24-field header puts `name` before `type`. The 24-value data row puts **type before name**, then writes the 18 hydrograph values. The final heading `null` corresponds to numeric temperature. [Hydrograph code selection](https://github.com/swat-model/swatplus/blob/aa4179fea9c9fbb9b00efc38e3d4def3b6a3f715/src/object_read_output.f90#L78) · [Hydrograph data order](https://github.com/swat-model/swatplus/blob/aa4179fea9c9fbb9b00efc38e3d4def3b6a3f715/src/obj_output.f90#L36) · [Hydrograph headings](https://github.com/swat-model/swatplus/blob/aa4179fea9c9fbb9b00efc38e3d4def3b6a3f715/src/hydrograph_module.f90#L546) |
| `sol_water` | The header has 16 fields, including ten layer headings `st_mm_1` through `st_mm_10`. A row writes name, type, and one storage value in mm per actual soil layer after its four dates. Its width is **6 + the number of layers**. The all-HRU branch writes one row per HRU with that HRU's own layer count. [Ten layer headings](https://github.com/swat-model/swatplus/blob/aa4179fea9c9fbb9b00efc38e3d4def3b6a3f715/src/hydrograph_module.f90#L721) · [Layer-dependent write](https://github.com/swat-model/swatplus/blob/aa4179fea9c9fbb9b00efc38e3d4def3b6a3f715/src/obj_output.f90#L47) |
| `solnut_ly` | The opener leaves the file without a header. The data list has 22 values per layer, including name and type after the dates, then the mineral N record, five organic N values, the mineral P record, and five organic P values. The writer omits the layer number. In the selected-object branch, the layer count uses `iob` while the values use `j`, which that branch leaves unchanged. The all-HRU branch takes its layer count from the zero object slot. These index choices limit interpretation of the requested HRU and layer. [Layer nutrient write and indices](https://github.com/swat-model/swatplus/blob/aa4179fea9c9fbb9b00efc38e3d4def3b6a3f715/src/obj_output.f90#L58) · [Mineral record members](https://github.com/swat-model/swatplus/blob/aa4179fea9c9fbb9b00efc38e3d4def3b6a3f715/src/organic_mineral_mass_module.f90#L58) |
| `solnut_pr` | The opener leaves the file without a header. The 32-value list contains the dates, name and type, mineral N and P records, and five complete organic mass records for active, stable, slow, and passive humus and residue. In the all-HRU branch the accumulators reset only after the HRU loop, allowing earlier HRUs to contribute to later rows. The residue loop also takes its plant count from `ihru` while summing the current `j`. [Profile nutrient sums and reset](https://github.com/swat-model/swatplus/blob/aa4179fea9c9fbb9b00efc38e3d4def3b6a3f715/src/obj_output.f90#L85) · [Organic mass members](https://github.com/swat-model/swatplus/blob/aa4179fea9c9fbb9b00efc38e3d4def3b6a3f715/src/organic_mineral_mass_module.f90#L7) |
| `plant` | The header contains 32 fields with two 13-field plant blocks. The data list uses name and type followed by 13 values for each plant actually present, giving **6 + 13 × plant count** values. The assembled data format joins consecutive repeat groups without a separating comma and uses `I` and `F` without widths. Successful plant rows require runtime verification. [Two header blocks](https://github.com/swat-model/swatplus/blob/aa4179fea9c9fbb9b00efc38e3d4def3b6a3f715/src/object_read_output.f90#L112) · [Plant write](https://github.com/swat-model/swatplus/blob/aa4179fea9c9fbb9b00efc38e3d4def3b6a3f715/src/obj_output.f90#L134) · [Fortran format requirements](https://www.intel.com/content/www/us/en/docs/fortran-compiler/developer-guide-reference/2024-2/format-specifications.html) |
| `cha_fp` | The header has 19 fields and the data list has 18. The extra `dormant` heading occupies position 9, which receives transmission loss (`tl`). Subsequent data values shift one position, and the last heading has no value. The zero-object branch reuses the zero object's name and type for its channel rows. [Floodplain headings](https://github.com/swat-model/swatplus/blob/aa4179fea9c9fbb9b00efc38e3d4def3b6a3f715/src/hydrograph_module.f90#L752) · [Floodplain data members](https://github.com/swat-model/swatplus/blob/aa4179fea9c9fbb9b00efc38e3d4def3b6a3f715/src/hydrograph_module.f90#L271) · [Floodplain writer](https://github.com/swat-model/swatplus/blob/aa4179fea9c9fbb9b00efc38e3d4def3b6a3f715/src/obj_output.f90#L156) |

The reader leaves `subday` unmapped. The check for that token inside the hydrograph writer and the writer's experimental carbon cases have no selectable code in this reader.
